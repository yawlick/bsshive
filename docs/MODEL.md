# BSS Hive

Калькулятор и подбор улья для Roblox-игры **Bee Swarm Simulator**: сколько мёда и пыльцы даёт улей,
на каком поле ему лучше, какой улей лучше всего для мёда, пыльцы нужного цвета или конкретного квеста.

- Сайт: `./run.sh` → http://localhost:8820 (всё считается в браузере, сервер раздаёт файлы и сохраняет калибровку)
  - вкладки полосой сверху (Улей / Статы / Цель / Калибровка / Результат), содержимое по центру, кнопки расчёта — справа в полосе;
    ссылки сразу на вкладку: `#hive`, `#stats`, `#badges`, `#amulets`, `#total`, `#goal`, `#calibrate`, `#result`
  - улей — сеткой лиц (как меню пчёл в игре): цифра уровня в углу (цвет = мутация), золотая рамка = Gifted, полоска = редкость;
    ЛКМ — редактор (уровень, Gifted, мутация), ПКМ или Delete — убрать, «+» (или `#add`) — окно выбора пчёл
  - сервер запускается с `node --watch` — сам перезапускается при изменении своего кода; данные — любые `data/*.json` верхнего уровня
  - **лодауты** (список слева) — готовые наборы «улей + статы + настройки подбора», например по одному на аккаунт:
    создать (`+ новый`), скопировать (⧉), переименовать (✎ / двойной клик / F2), удалить (✕, с «Вернуть»), перетащить
    мышью (на телефоне — за ⋮⋮) или Alt+↑/↓. Встроенный **«Лучшее»** — лучшее снаряжение, все бейджи Grandmaster и лучшие
    амулеты (`core/loadouts.js`); его улей и статы менять нельзя: любое изменение откатывается, и сайт предлагает копию,
    в которую это изменение попадёт. Настройки подбора (ограничения, замки, слоты) у каждого лодаута свои и меняются всегда;
    цель, поле и квесты — общие
  - сайт сам сохраняет лодауты в проект (`data/loadouts.json`, активный — ещё и в `data/my-hive.json`, `data/my-setup.json`) — их видит и Claude
  - `http://localhost:8820/?hive=Gifted Rad Bee x5 L10, Basic x10` — ссылка с готовым ульем (кнопка «Ссылка на улей»)
- Для Claude: MCP-сервер `bsshive` (`mcp/server.mjs`) — можно спрашивать прямо в чате
- Проверки: `node scripts/selftest.mjs`

## Структура

| `scripts/lua-table.mjs` | разбор Lua-таблицы `Module:Ability Tokens/data` (ничего не выполняет) |

| `core/gear.js` | статы игрока из снаряжения, бейджей, амулетов и строк «как в игре» (`playerFromSetup`) |

| `data/loadouts.json` | лодауты пользователя `{ rev, active, list }` (пишет сайт через `POST /api/me`; у встроенного хранятся только место в списке и `opt`) |
| `data/my-hive.json`, `data/my-setup.json` | копия активного лодаута (пишет сервер; в MCP — `hive: "my"`, `player: "my"`) |
| `core/quests.js` | `questPlan` — сколько времени займёт квест и на каких полях |
| `core/optimize.js` | `optimize` — подбор улья; `compareFields` — тот же улей на всех полях |
| `site/` | страница (`index.html`, `app.js`), расчёт в `worker.js`, сервер `server.mjs` |
| `mcp/server.mjs` | MCP-сервер, без npm-пакетов |

Обновить данные после патча игры / правок вики:

```bash
node scripts/fetch-wiki.mjs && node scripts/build-data.mjs && node scripts/selftest.mjs
```

### Данные из копии игры в Studio

Статы пчёл (`data/game-bees.json`) и иконки (`site/img/faces/` + `data/bee-icons.json`) взяты из клиентской копии игры, открытой в Roblox Studio.
Код игры только читается как текст, ничего из него не запускается. Это точнее вики. Найденные отличия:
сбор растёт на **5%** за уровень (на вики 10%); у Fire Bee сбор 10; у Demon Bee конвертация 60, мгновенная конвертация 20%
(30% у Gifted); у Carpenter Bee конвертация 120; у Vector Bee время конвертации 2.72 с; отдых в улье 15 с (у Shocked 7.5);
шанс пузыря у Gifted Bubble/Tadpole не растёт — в игре опечатка `GiftedBonues`.
Формул эффектов Beamstorm, импульсов, Triangulate и Fetch в клиентской копии нет: они в серверном коде.

Обновить из Studio (копия игры открыта, плагин MCPStudioPlugin подключён):
1. `node scripts/studio-receiver.mjs data/raw/game` — локальный приёмник на 127.0.0.1:8899;
2. в Studio через MCP `run_code` пройти `ReplicatedStorage/ReplicatedFirst/StarterPlayer:GetDescendants()` и для каждого
   `LuaSourceContainer` сделать `HttpService:PostAsync("http://127.0.0.1:8899/save?name=<FullName>.lua", d.Source)`;
   иконки — из `ReplicatedStorage.BeeModels`: цвет кубика (фон), декаль `FaceTexture` (номер картинки лица и Color3) → `_bee_models.json`;
3. `node scripts/build-game-bees.mjs` (покажет расхождения с вики) → `node scripts/fetch-bee-images.mjs` → `node scripts/build-data.mjs`.

MCP (уже зарегистрирован глобально):

```bash
claude mcp add bsshive -s user -- node /path/to/bsshive/mcp/server.mjs
```

Инструменты: `bss_bees`, `bss_fields`, `bss_quests`, `bss_gear`, `bss_evaluate`, `bss_compare_fields`, `bss_optimize`
(в т.ч. `lastQuests: 15` / `quests: [...]` и `limits`), `bss_next_step`, `bss_quest_plan`, `bss_calibrate`.
`hive: "my"` — улей активного лодаута, `player: "my"` — его статы; `"@Имя"` — любой лодаут (`hive: "@Основной"`,
`player: "@Лучшее"`), список — `bss_loadouts`; `setup: {tool, bag, hat, …}` — статы из снаряжения;
статы «как в игре» можно передать вместе с `statsFromGameHive` (улей, с которым их смотрели) — бонусы этого улья вычтутся.

## Статы игрока

Два способа (переключатель на вкладке «Статы»):

1. **Из снаряжения** (по умолчанию). Выбираешь инструмент, рюкзак, маску/шапку, ремень, ботинки, два щитка (данные с вики),
   уровень бейджа в каждой категории (действует только высший), собираешь амулеты в **конструкторе** и всё прочее
   (бикипы, стикеры) строками «как в игре». Итог считается как в игре: **(база + все «+») × все «x»**;
   «+350,000 Capacity» прибавляется к объёму рюкзака, «+75% Capacity» и «x1.5 Capacity» — к множителю.
   Вкладка «Итог» показывает каждый стат и откуда он взялся, а также строки, которые не влияют на мёд (атака, защита, удача)
   или которые калькулятор не понял. Бонусы Gifted-улья сюда не входят — их добавляет модель для того улья, который считает.
2. **Вручную из ⚙️.** Цифры из меню игры. Там они уже включают бонусы Gifted текущего улья, поэтому по умолчанию
   калькулятор сначала вычитает бонусы «моего улья» (`stripHiveBonuses`), иначе при подборе они посчитались бы дважды.

**Конструктор амулетов** (вкладка «Амулеты»): все амулеты игры — Star/Ant/Shell/Cog от Bronze до Supreme, Stick Bug до Diamond,
Moon, King Beetle (`data/amulets.json` ← `node scripts/build-amulets.mjs` из `ReplicatedStorage.Amulets`). У каждого — обязательные
строки (диапазон значений, редкие — с шансом) и пулы «N строк из списка»: выбираешь, какие строки выпали, значения — ползунком или
числом, больше N не даст. «Всё на максимум», «Строками» (вписать вручную). Строки, которые модель не считает (атака, бонд, защита),
помечены «не влияет». Источник правды — по-прежнему строки амулета (`a.lines`); `core/amulets.js` разбирает их обратно
(`parseAmulet`) и по ним же определяет тир старых амулетов, сохранённых только строками (`amuletDef`). В MCP — `bss_gear slot: amulets`.

**Баффы, которые держишь всё время** (вкладка «Баффы»): предметы и коды (Super Smoothie, Enzymes, экстракты…), ваучеры,
благословения цыплят, нектары, желейные бобы (со стаками) — из кода игры (`data/buffs.json`). Выбор — `setup.gear.buffs = { имя: стаков }`;
строки баффа (`buffLines` в `core/gear.js`: «+» растёт на значение за стак, у бобов — на `perStack`; «x» — линейно, как Combo в игре)
идут в статы как «бафф X». Есть все баффы игры, кроме дебаффов, Polar Power / Science (поля на «Статах») и баффов, которые модель считает сама из токенов пчёл и пассивок (Red Boost, Inspire, Focus, Baby Love, метки, Flame Heat, морфы…; `MODEL_KEY` в build-icons). Механизм `player.forcedBuffs` (держу всегда) в модели остался, но с сайта не задаётся.

**Иконки токенов и баффов** (`node scripts/build-icons.mjs`, нужен `data/raw/game`): как в игре — круг цвета фона и картинка,
умноженная на свой цвет. Токен-бафф берёт вид из описания баффа (`Color`, `Icon`, `IconColor`; нет `Icon` — Decal «<Бафф> Icon» в
`Buffs`, и цвет фона тоже его), бомбы — `Collectibles.PollenBomb.Visuals` (цвет картинки по самой сильной пыльце), остальное —
`Collectibles.<Тип>.Visuals`. Модули Mark, Scratch и Target Practice в копии не декомпилировались — для них Decal `Icon` модуля
(метки — вид баффа метки, Target Practice — фон цвета Precise Bee). Картинки — `site/img/icons/<id>.png` (API миниатюр Roblox),
данные — `data/token-icons.json`. На сайте — в «Результате» (источники пыльцы, конвертация, баффы) и на вкладке «Баффы».

Пассивки снаряжения считаются там, где описаны в `core/passives.js`; остальные перечислены в «Итоге».

## Улей текстом

`Gifted Rad Bee x5 L10, Basic Bee x10 L8, Gifted Tabby Bee L12` — `Gifted`/`G`/`🌟` в начале, `xN` — сколько, `LN` — уровень
(по умолчанию 1 штука, уровень 10). Имена можно без `Bee` и сокращать: `rad x5`.

## Как считает модель

Средние значения (матожидание); посекундно симулируется только появление токенов (это дёшево и кэшируется).

**Пчела** (формулы со страницы вики *Stats*):
- сбор = база × (1 + 0.05·(ур−1)) × 1.5 (Gifted) — +5% за уровень по коду игры; +50% с цветков своего цвета (только красные/синие пчёлы);
  × средний размер цветка поля (x1/x2/x3, со страницы поля; см. `flowerSizeForBees`)
- скорость = база × (1 + 0.03·(ур−1)); один «цикл» = время сбора + перелёт `flightStuds / скорость`
- энергия = база × (1 + 0.05·(ур−1)); когда кончилась — летит в улей (0.5× скорости), отдыхает 15 с (код игры), летит обратно (1.5×).
  Доля времени «бодрствует» = активное время / (активное + сон). Photon и Exhausted не спят.
- конвертация = (база + Convert Amount) × (1 + 0.1·(ур−1)) × Convert Rate × 1.5 (Gifted) / время

**Токены** (кулдауны — из `Module:Ability Tokens/data`, это копия данных игры; правила — со страницы вики *Ability Tokens*
и таблицы датамайна токенов). Частота считается симуляцией одной пчелы (`core/spawnsim.js`):
попытки — только на остановках у цветка (время перелёта случайное), попытка — если прошли use и try cooldown,
удачная попадает в пул, из пула выпадает один токен за остановку; Bee Ability Rate делит кулдауны и умножает шанс;
энергия и сон; у токенов с `StartWithFullCooldown` (в таблице датамайна отмечены *) кулдаун после сна начинается заново.
По сравнению с формулой вики «use + try·(1/success − 1)» это даёт заметно меньше токенов у пчёл с несколькими способностями
(Music Bee: Focus и Token Link −30%), у Honey Gift (сброс после сна, почти вдвое) и у редких токенов вроде Inspire.
Игрок подбирает `tokenPickup` из них.
- стакающиеся баффы (Boost, Focus, Inspire): среднее число стаков считается точно для потока токенов
  (каждый новый токен продлевает бафф, при паузе длиннее баффа стаки сгорают)
- обычные баффы (Baby Love, Bear Morph, Melody…): доля времени, когда бафф активен = 1 − e^(−частота × длительность)
- метки (Pollen/Honey Mark): бафф, только пока игрок стоит в метке (`markStand`)
- бомбы: 13 / 29 цветков × сила из данных игры (7 или 10) × (1 + 0.1·(ур−1)) × множители бомб
- пузыри (Bubble, Tadpole) и пламя (Fire, Demon): шанс на каждый сбор, формулы со страниц *Bubble* и *Flame*; Flame Heat → до x2 красной
- Bomb Sync (Crimson/Cobalt): красные/синие бомбы собирают белые цветки, +10% пыльцы цвета и +10% мгновенной конвертации;
  Gifted-импульс мгновенно конвертирует 25% Convert Amount каждой пчелы на пути

**Мутации** (цвет цифры уровня = вид; данные `Module:Mutation Stats/data`): «×» умножает итоговый стат пчелы,
«+» прибавляется к базе. Учитываются сбор, конвертация, энергия, скорость, мгновенная конвертация, крит и Ability Rate (атака — нет).
На сайте — кнопка ☢ у пчелы; текстом — `Puppy Bee L9 M:ConvRateMul=1.1`.

**Пассивки снаряжения** (`core/passives.js`, цифры с вики Passive Abilities): каждая срабатывает от счётчика токенов,
частота — из модели. Haste/Focus Pulser — импульсы; Bubble Bombs — пузыри; Ignite, X-Flame — пламя; Diamond Drain, Coin Scatter,
Star Shower (пойманные звёзды), Inspire Coconuts, Petal Storm — «пачки» конвертации прямо на поле;
Pop Star — x2…x4.5 синей и Bubble Bloat до x6 (Blue Field Capacity и Convert Rate at Hive); Scorching Star — x2…x5 красной,
ссылки конвертации и опустошение рюкзака в конце (если рюкзак не успевает заполниться — в улей не ходим);
Guiding Star / Star Shower — ×1.25 вместимости, Pop/Scorching/Gummy Star — ×1.25 Field Capacity своего цвета.
Не считаются: Coconut Haste, Combo Coconuts (другие игроки), Goo Trail/Gummy Morph (слизь), Star Saw (Stinger), Emergency Coconut Shield.

**Буст поля** — на вкладке «Цель»: стаки Field Boost выбранного поля (0–4, каждый +100% пыльцы); глиттер и прочие проценты — строками в «Прочее».

**Улей и рюкзак**: бонусы Gifted (каждый вид — один раз) добавляются к статам игрока.
Instant Conversion, суперкриты, Honey Mark, Star Shower, кокосы и т.п. превращают часть пыльцы в мёд прямо на поле.
Модель берёт лучший из трёх режимов (`cycle.mode`):
- `never` — рюкзак не наполняется: всё, что попало в него, успевает сконвертироваться на поле;
- `hive` — цикл: набрать рюкзак + сходить в улей + конвертировать (все пчёлы улья) + вернуться;
- `stay` — стоять на поле с полным рюкзаком. В игре при полном рюкзаке сбор останавливается (`Collectors.LocalCollect.HasCapacity`),
  поэтому собирается только `stayShare` от полного сбора — столько, сколько успевает сконвертироваться на поле. Без этого режима
  у модели был обрыв: улей на границе «рюкзак не наполняется» терял мёд от любой лишней пыльцы, и подбор набирал слабых сборщиков.
Для квестов на пыльцу берётся «пыльца в час» лучшего по пыльце режима.

**Криты**: шанс крита × сила; суперкрит бывает только у крита, даёт ×2 силы (Super-Crit Power) и **100% мгновенную конвертацию**
(код игры, описание Target Practice). **Precise Bee** (Target Practice): все 3 мишени (ГРУБО: вероятность `targetsHit³`) — стак
Precision, +2% суперкрита на 60 с, до 10; выстрелы мишеней с Flame Heat — до ×4 пыльцы и до 50% мгновенной конвертации.
Каждая активированная мишень даёт токен Focus, неактивированная — Red Boost. **Выстрел по игроку**, стоящему на мишени
(ГРУБО: доля `targetStand` 0.7), конвертирует рюкзак: (50% Convert Total + 10× конвертации пчелы) × до 10 от Flame Heat ×
до 3 от стаков буста поля; половина — токенами мёда. Этот выстрел **съедает Flame Heat**: средний разогрев считается от того,
как часто стреляют мишени и за сколько он восстанавливается (ГРУБО: `heatRefill` 6 с) — поэтому Precise не бесконечно полезны.
**Precise Mark** (Gifted, ГРУБО: доля `preciseMarkShare` 0.4 токенов, живёт как Pollen Mark+): +7% крита и суперкрита за стак, до 3;
Triangulate и Mark Surge в ней всегда критуют.

**Атака пчёл** (BeeStats.GetAttack): (база + Bee Attack всем и своего цвета) · 1.5 у Gifted · Bee Attack Multiplier (строки
«+15% Bee Attack», Gifted Rage Bee, Flame Heat +2…25%). От неё — выстрелы Target Practice («двойная атака пчелы»). Rage — только в бою.
**Уровень пчелы** (BeeStats.BonusesPerLevel): сбор +5%, конвертация +10%, энергия +5%, скорость +3% за уровень; способности —
+10% за уровень (их описания). Инструмент, пассивки снаряжения (X-Flame, Ignite, Star Shower) от уровня пчёл не зависят.

**Spicy Bee**: Inferno — 6 пламён и 2 временные Fire Bee на 15 с (+1 с за уровень), уровень на 2 ниже, у Gifted — шанс Gifted
(они собирают и зажигают пламя, но в улей не летают); Flame Fuel (Gifted) — 15 с пламя горит на 50% дольше и при появлении
конвертирует 50 тыс. + (10 + 5 за стак буста)% Convert Total; Steam Engine — сбор и скорость до +100% от Flame Heat (два прохода:
разогрев зависит от пламени улья). **Instant Flame / Bubble Conversion** (Demon/Fire Mask) — мгновенная конвертация пыльцы пламени и
пузырей. **Mark Surge** продлевает все активные метки на 1 с (+0.1 с за уровень), до 5 раз на метку.

**Буст поля** — стаки Field Boost (Zone_Buffs: до 4, каждый +100% пыльцы поля); от них же растут Target Practice (до x3),
Star Shower (+100% Convert Total за стак), кокосы (+25%) и Flame Fuel. В MCP — `fieldBoostStacks`.

Сверено с игрой: Convert Total модели (352 453) = ⚙️ пользователя (353 746) — Convert Rate в него входит.
Статы амулетов Cog «Event Bee Pollen» (сбор и токены ивентовых пчёл) и «Mark Ability Pollen» (токены с тегом Mark) — учитываются.

**Подбор** (`optimize`): жадно заполняем слоты (каждый следующий — та пчела, что даёт больше прироста),
потом меняем «одну пчелу вида A на вид B», пока становится лучше; вторая попытка стартует с моего улья (`seed`),
так что результат не хуже своего улья. Цель — мёд, пыльца (цвет) или **несколько квестов сразу** (минимум суммы времени,
`questsPlan`). Ограничения по каждой пчеле (`limits`): можно/нельзя, максимум штук, **максимум Gifted**, уровень
(свои пчёлы — со своим уровнем). Прогресс и отмена на сайте; лимит времени 25 с для квестов.

**Следующий шаг** (`nextSteps`): лучшие одиночные замены в моём улье (для тех, кто меняет пчёл по одной через Royal Jelly),
с ценой в Royal Jelly (шансы с вики: редкая ~70%, эпическая 27%, легендарная 3%, мифическая 0.004%, Gifted 1/250;
внутри редкости виды равновероятны → конкретная редкая ~13 RJ, эпическая ~41, легендарная ~267) и сортировкой
«по выигрышу» или «по выигрышу на 1 Royal Jelly». **План замен** (`swapPlan`) — N лучших замен по порядку с результатом после каждой.
Royal Jelly оставляет пчеле уровень и бонд (слова NPC в клиенте игры), а Gifted и мутация пропадают (вики) — новая пчела
в замене получает уровень заменённой.

**Закреплённые пчёлы** (`limits[name].lock`, 🔒 на сайте): подбор их не убирает (в `optimize` — группы `fixed`, в `nextSteps` — не
в списке «что убрать»). Пресет «Реалистично» (по умолчанию): редкие и эпические — сколько угодно, легендарные — не больше своих +2,
ивентовые и мифические — только свои (из Royal Jelly их не получить). Не закреплены: убранная ивентовая пчела даёт особое желе,
которым её можно вернуть.

**Ивентовые пчёлы** каждого вида — не больше одной в улье (как в игре): `EVENT_MAX` в `core/optimize.js` срезает любые лимиты
(и в `optimize`, и в `nextSteps`), сайт не даёт ввести больше.

**Прогресс подбора** («лучший пока») — максимум за весь подбор: второй заход (улучшение от своего улья) начинается ниже первого,
поэтому показывать его текущий счёт нельзя.

**Встроенный лодаут «Лучшее»** (`core/loadouts.js`): снаряжение — в каждом слоте то, что даёт больше всего мёда в модели
(подбор по слотам, среднее по Pine Tree, Rose, Pumpkin, Coconut, Mountain Top): Dark Scythe, Coconut Canister, Diamond Mask,
Coconut Belt, Gummy Boots, Cobalt + Crimson Guard. Амулеты — высший вид каждого (Supreme, у Stick Bug — Diamond) с
максимальными значениями строк из `data/amulets.json`; строки из пулов «Select N» выбраны перебором (больше мёда, при равенстве —
больше пыльцы; строки, которые модель не считает, — только если в пуле больше нечего взять); строки про поля (Zone) — для средних полей. Science 31 (предел), Tabby Love 1000; Polar Power 0 — предела у него нет. Улья нет — его подбирают.

**Скорость**: часть расчёта, не зависящая от поля (статы пчёл, токены, баффы), кэшируется для одного улья —
план из 15 квестов (~20 полей) считается за ~2.5 мс.

## Слизь, лягушки, кокосы

- **Слизь (goo)** — вики Goo: с лужи из f цветков бонусный мёд = собранная пыльца · √(f/200); стат **Goo** (Gummy Mask/Boots, Shell Amulet)
  умножает слизь, **Honey Per Goo** — мёд за неё, **Goo Conversion** мгновенно конвертирует столько пыльцы, сколько собрано слизи.
  Слизь собирают игрок, пчёлы и способности. Лужи: Glob (49 цветков, Gifted 81 — код игры), Gumdrop Barrage, Goo Trail (Gummy Boots),
  Gummy Morph (Gummy Mask: каждый 10-й токен Gummy Bee — всё поле в слизи, 10 с +75% Goo, +100% Goo Conversion, Gummy Bee +1000% сбора).
  Покрыто цветков = Σ частота · площадь · `gooLife`; доля пыльцы со слизью = покрыто / `gooZone`. Квесты «собери N слизи» считаются.
- **Summon Frog** (Tadpole): лягушка живёт 20 + 2·(ур.−1) с (код игры), пузыри — на 3 прыжках из 4 (вики), прыжок раз в `frogHop` с.
- **Coconut Haste**: пойманный кокос — стак Haste. **Combo Coconuts**: каждый 40-й кокос — бафф Coconut Combo (BuffDefs: 30 с, значения
  линейно от 1 до 100 стаков: x1.2…x2 пыльцы, 25…75% мгновенной конвертации, +1…50% цветной пыльцы, Honey From Tokens и атаки), стаков `comboStacks`.
- **Inferno**: у временных Fire Bee считаются и их Red Bomb+.
- **Star Saw** (Star Amulet): каждый 3-й Stinger — пила на 30 с, 10 раз в секунду собирает и сразу конвертирует 3 (+0.5 за 100 Attack Total)
  с 5 цветков и столько же конвертирует из рюкзака (код игры). Stinger — раз в 30 с, если на вкладке «Баффы» включён бафф Stinger; иначе пила не считается.
- На мёд с поля не влияют (результат показывает их отдельно): Sniper (бой), Nectar Lover (плантеры), Emergency Coconut Shield, Impale, Mind Hack, Rain Cloud.

## Что пока приблизительно

Требования «убей N мобов» в квестах не считаются совсем (так решили). Не учитываются: Tornado (Windy), шарики Buoyant, Pollen Haze (Fuzzy),
Glitch/дубли токенов, Festive-подарки, Gummy Star (звезда появляется только от предмета Gumdrops), шар Gummyballer,
способности инструментов (столб Porcelain Dipper и т.п.), статы бикипов на отдельной пчеле
(бонусы улья от бикипов можно вписать строкой в «Прочее»), **истощение цветков** (данных о скорости отрастания нет ни на вики, ни в клиенте игры).
Шарик улья (Hive Balloon) наполняется только от шаров-предметов и Buoyant Bee — обычную конвертацию не меняет; Balloon Blessing можно вписать строкой.

Грубые оценки (чисел нет ни на вики, ни в клиентском коде игры — эффекты считает сервер) помечены в результате:
Beamstorm (`beamFlowers`), Triangulate (`triangleFlowers`), импульсы Cobalt/Crimson (`pulseBase`, `pulseHopGrowth`), Fetch (`fetchKicks`),
Flame Heat и рост Scorching Star (`flamesForMaxHeat`), Bubble Bloat, Petal Storm (`petalHits`), Movement Collection (`stepFlowers`),
слизь (`gooLife`, `gooZone`, `barrageFlowers`, `barragePuddle`, `trailFlowers`, `trailPuddle`), лягушка (`frogHop`), Coconut Combo (`comboStacks`).

## Калибровка

Абсолютные числа модели — оценка «по вики». Подгонка по замерам из игры — три коэффициента
(`gatherScale`, `tokenScale`, `convertScale` в `CALIBRATION`), каждый из своего замера:

1. **Стоять на месте** N минут (5–10) с пустым рюкзаком, токены не собирать, инструментом не кликать → `gatherScale`
   (сбор пчёл и пламя — то, что идёт само).
2. **То же, но собирать токены и лопать пузыри** → `tokenScale` (пыльца способностей и пузырей).
3. Необязательно: **сколько пыльцы сконвертировалось в улье за S секунд** → `convertScale`.

Пыльцу смотреть на полоске рюкзака; рюкзак не должен заполниться (модель предупредит).
Улей, поле и статы в калькуляторе должны быть как в игре.
Где вводить: на сайте блок «Калибровка по замеру из игры» (`/#calibrate`) или в чате (`bss_calibrate`).
Результат сохраняется в `data/calibration.json`, и его автоматически используют сайт и все инструменты MCP.
Остальные константы без источника (`flightStuds`, `hiveTripStuds`, `tokenPickup`, `markStand`, грубые оценки способностей)
тоже в `CALIBRATION` — их можно передать в любой расчёт (`calibration: {...}`).
